227 AI / Field Manual

Know your pocket assistant.

The controls, defaults and boundaries of 227 AI. A local model, a controller-first interface, and files you can inspect on your own card.

640 x 480 interfaceLocal inference and speechNo cloud account

Controls

Controls depend on the active screen. In particular, B is not always Exit and Y is not always New Chat. Read the current footer before acting in history or an editor.

Main conversation

AStop active read-aloud; otherwise read the reply under the pointer, or open the keyboard when ready.

BRequest generation cancellation while a reply is active; otherwise exit from the main screen.

Message keyboard
ControlAction
D-Pad / AMove between keys / activate the selected key. The left stick can also position the pointer.
X / YSend the draft / insert a space.
BDelete one character; close the keyboard if the draft is already empty.
Up from the top rowFocus available word suggestions. Move Left/Right and accept with A; Down returns to keys.

SPACE / DEL / SEND / CLOSEExplicit action keys; CLOSE hides the keyboard without sending the draft.

Suggestions are prefix matches from the local word list, not predictions from a remote service. Dictation inserts text into the draft; it does not automatically submit a question.

Chat history
ControlAction
D-Pad Up / DownSelect a saved conversation.
AOpen the selected chat.
X / BClose history.
YDelete the selected saved chat. Treat this as a destructive action, not a new-chat shortcut.

Opening an older chat does not give the model unlimited memory of it. Stored messages and the much smaller inference context are separate things.

Settings

Press R2. Up/Down selects a page in the left navigation; Right or A focuses its values. Up/Down then selects a row, Left/Right changes supported values, and A selects or adjusts. B closes Settings outside the prompt editor. Most accepted changes save immediately to config.json.

These are the UI's choices, not a claim that arbitrary JSON values are accepted unchanged. The loader clamps context to 512-1024, reply limits to 48-256, temperature to 0-1 and speech speed to 0.75-1.5. Prefer the interface for normal changes. Generation also uses fixed top_k=40, top_p=0.9 and repeat_penalty=1.08.

The six pages

MODELS selects among present files. SYSTEM PROMPT edits the instructions used for the next answer. GENERATION holds context, reply and temperature controls. VOICE holds highlighting, rate, device selection and the microphone test. APPEARANCE controls the static background and intro. SYSTEM INFO shows the target profile, inference setup and data path; its target-profile labels are not a hardware certification scan.

Changing the model or context reloads the engine in place while retaining the chat and draft. A change requiring an engine reload is rejected while generation, dictation or another engine transition is active. A failed save or missing background reports a note rather than silently claiming success.

System prompt editor

Choose EDIT, type using the on-screen keyboard, or use its own MIC key to dictate. X applies, B deletes, Y selects all, and L1 inserts a newline. The action row provides MIC, SPACE, DEL, ALL, APPLY and CANCEL. APPLY requires nonempty text; CANCEL discards the draft. RESET on the prompt page restores the built-in instructions.

The default prompt asks 227 to be concise, useful and honest, acknowledge uncertainty, check constraints and arithmetic, and keep normal replies under 100 words unless more detail is requested. This is guidance to a small language model, not a correctness guarantee.

The runtime archive's adjacent .sha256 sidecar must agree with the core's pin, and the archive itself is hashed. Installed runtime reuse checks actual files against its manifest and requires executable engine binaries. These pins cover those binaries and models, not every remote source file. The local online core resolves GitHub main via the API and stages source from an immutable commit; that snapshot is not a signed release or a version baseline.

Optional profiles are not installed models

The app recognizes Qwen3-0.6B-Q4_K_M.gguf as smart and Falcon-H1-0.5B-Instruct-Q4_K_M.gguf as falcon if those exact files exist in models/. The installer does not download them. File presence makes a profile visible; it does not establish runtime compatibility, memory fit, speed or answer quality. No comparative benchmark is supplied here. Check each optional model's own license before obtaining or redistributing it.

Speech and microphone setup

Speech recognition and synthesis are offline but separate. Whisper turns a short recording into draft text; espeak-ng reads a selected reply. This is not an always-listening assistant or a continuous voice conversation.

  1. Connect a usable USB microphone. Do not depend on an internal R36S microphone path.
  2. Open R2 > VOICE > MIC / SPEAKER and choose Auto or a detected device. Saved device identities survive ALSA card renumbering when the same identity is available.
  3. Select TEST MICROPHONE. It records about four seconds, analyzes the signal and attempts playback through the selected device. A capture-only USB device may not provide a playback endpoint.
  4. In the message keyboard or prompt editor, activate MIC, speak clearly, activate it again, and wait for transcription. Review the text before sending or applying.

Capture uses mono, 16-bit PCM at 16 kHz. The shipped speech model is English-only tiny.en, and the transcription command explicitly selects English. Recording is capped at 30 seconds; transcription can take additional time. The microphone test's signal verdict is a troubleshooting aid, not a transcription accuracy score.

Read-aloud uses the operating system's libespeak-ng.so.1, with an English voice and a baseline of 175 words per minute at 1.0x. Word timings drive optional highlighting. Only the first 600 characters of a selected reply are passed to synthesis. Speech output is synthetic; it does not provide a natural-voice quality guarantee.

On a confirmed install/update, the installer checks libespeak-ng.so.1 and usable English voice data, plus arecord, aplay, amixer and pkill. Missing capabilities map to libespeak-ng1, espeak-ng-data, alsa-utils and procps. The restricted helper can install these only on supported Debian/Ubuntu-family aarch64 firmware with dpkg arm64, APT and root or sudo -n; no password is requested. Unsupported/no-admin cases report an error and missing-package list. A functioning audio device route is required regardless of installed packages.

Working capabilities cause no package queries or system changes. Missing-capability setup audits and version-pins the complete dependency closure with --no-upgrade --no-remove --no-install-recommends, rejects upgrades/removals and protected Mesa/EGL/GLES/GBM/DRM/Mali graphics/firmware packages, and refreshes indexes only if initial simulation fails. Broken existing libraries are not automatically replaced. Desktop, help, dry-run and uninstall skip automatic setup. Packages consume system-partition space outside the SD budget and app rollback, and stay installed after uninstall. Cancellation waits for running APT to finish; do not power off during setup.

Useful diagnostics include /tmp/project_227_mic.log and the microphone-test status. There is no separate MIC TEST launcher; Update / Repair removes the old standalone test entry.

The app resolves its data directory relative to its own Python file, so it can run from either app card. Back up all three JSON files before removal. A retained manager is not a backup of deleted chats.

Fresh app staging budgets about 650 MiB, or about 25 MiB additional space if the installed runtime and both models verify; these are not exact installed sizes. Retained partials can reduce the budget. Shared system dependencies use separate system-partition space and are not removed with the app.

Privacy boundaries

Normal app operation has no external network dependency: model inference and speech processing happen on the handheld. The Python app talks over HTTP to its own llama.cpp server at 127.0.0.1:39227. That is loopback communication, not a cloud endpoint. The server is launched in offline mode, bound to loopback, with its web UI disabled.

The installer is different: it contacts GitHub (including the API for local-code online update checks) and, when needed, Hugging Face. Automatic dependency setup may also contact configured APT repositories when capabilities are missing. Those services can see ordinary requests and connection metadata. Downloading a model is not uploading a chat. The website does not require an account or trackers, but following an external source link leaves this site.

Local is not encrypted. Settings and conversations are plain JSON on the card. Anyone with access to the card or a sufficiently privileged process can read them. There is no app-level password, encrypted vault, secure deletion or cloud backup.

Audio and diagnostics also have a local footprint. Capture uses /tmp/project_227_mic.wav; microphone testing uses /tmp/project_227_mictest.wav. Synthesis uses temporary WAV filenames based on project_227_tts. Normal cleanup removes some playback files, but the app does not promise that every recording or log is automatically erased, especially after an interrupted session.

/tmp/project_227_mic.log can include a transcript excerpt, and /tmp/project_ai_server.log contains engine diagnostics. Manager/bootstrap/CLI logs remain in their own directory. Do not assume /tmp is persistent or automatically secure; its lifetime depends on the operating system. Review files and logs before sharing an SD image or bug report. Uninstall is ordinary file removal, not forensic erasure.

Practical and hard limits

Current source limits
BoundaryLimit
Message draft500 characters, including inserted dictation.
System prompt2,000 characters; nonempty when applied.
Microphone recording30 seconds per dictation; the test records about four seconds.
Read-aloud inputFirst 600 characters of the selected reply.
Saved chatsUp to 60 entries.
Recent history fileUp to the last 24 message entries before pending/transient entries are filtered, not 24 conversations.
Context / reply budget768 / 160 tokens by default. Tokens are not words or characters.

The request builder trims older messages using a roughly 2,100-character budget with per-message overhead, then prepends the system prompt. This is not token counting, and it is not a promise that a long prompt fits the configured token context. Keep custom instructions short and restate crucial details in a new question.

A 350-million-parameter model on this handheld is a constrained assistant, not a substitute for verified information. It can invent facts, make arithmetic errors, miss instructions and forget earlier context. There is no live web search or current-data feed. Do not rely on it for medical, legal, financial, emergency or other safety-critical decisions.

Known pitfalls

  • Arithmetic is not a dependable built-in calculator. The current source has a broken expression-helper path; do not treat calculator-looking input as a verified computation feature.
  • A profile is not a downloaded model. Qwen and Falcon appear only when their files exist; the standard install fetches LFM and English Whisper.
  • A new SD destination is not a migration. It repoints the shared launcher registration without erasing the old copy.
  • Repair is not manager self-update. Four deployed manager modules are cached separately from the app payload. A complete set is reused; updating the bootstrap and matching set is manual. If a module is absent, the new bootstrap refreshes all four rather than mixing versions.
  • Up to date is a content check, not a guessed version. The local backend returns up_to_date only after managed source, actual model/runtime hashes, owned ES/theme metadata, executable permissions and config existence pass. It skips app writes, preserves ES statistics and ignores harmless XML rewrites. Missing/integrity failures trigger repair; differing existing payload bytes use Updated/repaired files because corruption and a new version cannot be reliably distinguished without a release baseline.
  • Cache does not prove freshness. Online checks require internet even for a no-op; GitHub API/rate-limit and source-fetch failures cannot report up to date. Local source/bundle checks explicitly compare the local tree, not GitHub. See Updates and repair.
  • A saved chat is not unlimited model memory. A long archive can outlive the short context supplied for the next answer.
  • Offline does not mean no local traces. JSON, recordings and logs deserve the same care as other private files.
