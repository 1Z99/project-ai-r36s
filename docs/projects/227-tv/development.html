227 TV / Build Notes

One handheld screen. No compositing mistakes.

How the atlas renders, why it insists on owning the display, and what was actually verified on the handheld. Implementation facts are evidence, not blanket compatibility claims.

Architecture

The Python code uses the standard library only, with no pip dependencies, but the application is not dependency-free: it needs native SDL2/SDL2_ttf, a compatible libmpv and firmware media/audio libraries. SDL and libmpv are called through ctypes; the shell launcher invokes flock. Network operations run in workers and return results to the UI queue. There is no project-hosted playback server: unlike the desktop Qt Multimedia/HLS-proxy implementation, the handheld contacts playlists and stream hosts directly.

Display ownership

On the handheld the launcher uses SDL_VIDEODRIVER=kmsdrm and SDL_RENDER_DRIVER=software, selecting the verified firmware /usr/lib/aarch64-linux-gnu/libMali.so for SDL EGL/GL when present. Before creating any SDL window, the app rejects unowned KMSDRM launches: it records the real EmulationStation ancestor PID and start time, and exits if that owning process disappears or the launcher is orphaned. KMSDRM startup can queue misleading hide/focus-loss events, so ownership is decided by the ES process relationship, never by window-manager focus.

Background joystick delivery is disabled; exiting releases players, audio and SDL resources. The launcher appends stdout/stderr to the data root's app.log, guards duplicate launches with flock, creates a private XDG_RUNTIME_DIR only when none is valid, and returns control to ES on exit.

The refusal is before window creation, but not a sandbox. Normal deployment simply starts the app from the menu. Remote starts, nohup, & or background services are explicitly not supported paths.

Globe rendering

Drawing the spinning Earth every frame on this CPU is a budget exercise, so the renderer caches:

  • Cached presentation. Globe images use smooth CPU-filtered scaling at native display size, cached until camera, selection or quality changes. Menu/detail transitions crossfade over 200 ms instead of popping.
  • Native overlay lines. Coastlines, country borders and the Earth rim are drawn after scaling at one native pixel, so low globe-resolution settings cannot thicken them; country close-ups switch to a once-built geographic polygon fill with lakes and holes retained.
  • Native helper, graceful fallback. A compiled ARM64 native/libtvglobe.so provides the CPU projector/scaler; a missing or wrong-architecture library falls back to SDL's filtered scaler, so desktop previews work without it. Recorded handheld benchmarks: about 6.8 ms for a 224x224 to 406x406 scale versus roughly 25 ms through SDL filtering, and about 6.5 ms for the native 160x160 world projector before scaling. These are scaling timings, not whole-frame guarantees; SDL composition and presentation add more.
  • Polite idle motion. The world rotates at 2.4 degrees/second (adjustable Off, 0.5x-8x), with up to 15 Hz updates and an eased start after two seconds without globe interaction. It requires world browsing, no modal/country/flight, zoom at most 1.5x, active input focus, no drag and a pointer away from the globe. Unrelated list input does not reset the globe-interaction timer.
  • Crystal-green style. The Earth palette is ocean 5,19,12 / land 13,62,34 with mint country borders 64,196,104, a matching mint rim, and an amber selected country and channel-count numeral. The square panel behind the Earth is translucent (alpha 90), so the interface's scanline backdrop shows through.

Manual zoom is eased and starts at x0.8. Movement detail is capped at 224 px regardless of configured stationary resolution; count labels, cursor and text stay native. The cached geometry also powers the selected country's dark-green border trace at 12 Hz without rebuilding the image.

Playback runtime

Video plays through libmpv's api_type=sw software RGBA render API: pixels arrive in application memory, then SDL composites them. This deliberately avoids the GBM/EGL hardware path that the firmware's libgbm cannot satisfy, and works with SDL's KMSDRM window instead of an mpv vo window or GPU surface. Audio goes through ALSA; exiting playback closes the decoder, audio output and pending quality selection.

Single playback uses a 640 x 480 output surface. Matrix playback creates up to four 298 x 218 surfaces; the historical four-decoder benchmark instead used 320 x 180 test outputs at about 14 frames/s each with audio-focus handoff. It was neither a four-live-stream test nor a matrix-display benchmark. Output dimensions do not cap source decoding cost. Focus first disables audio on all players and waits for active audio to stop before enabling the selected cell.

Rendition choice never transcodes: Auto prefers the highest advertised source at or below 480p for single playback, 240p in matrix, while higher-only or unknown sources can still play. The UI lists discovered source resolution/FPS combinations, not fabricated frame-rate controls. Where HLS uses separate audio, a private one-rendition master preserves associated media groups and is removed when the player closes. Quality changes restart only the focused cell and do not rewrite favorite/recent snapshots. Unknown dimensions are observed after decode; high-resolution sources receive a warning, not a hard block.

Single video is already fullscreen; watch chrome hides after about 2.5 seconds without input. There is no fullscreen-toggle or matrix-cell maximize action. A pauses/resumes with button navigation; pointer activation in the matrix selects a cell. B dismisses a modal first, then stops playback from the unobscured watch view. Start alone keeps decoders/audio running. See the contextual control map.

Private runtime build

build_runtime.py is the recipe that produced the bundled runtime, run on the handheld by an explicit authorized session. It is not part of installation and never uses sudo, apt install/update/upgrade, pip or system library writes; missing tools fail the build rather than being installed.

  1. Pinned acquisition. It downloads libmpv2=0.40.0-3+deb13u1 documentation and dev/tool packages with apt download, pinning every candidate version into packages.lock.json (rebuilds accept --lock to reuse it or the output manifest). An unavailable locked package fails rather than substituting.
  2. Source verification. mpv 0.40.0 plus Debian's 0.40.0-3+deb13u1 source and patches are fetched over HTTPS, and archive SHA-256 values are validated against Debian's .dsc (from Debian HTTPS; no independent OpenPGP trust verification is claimed).
  3. Build. Prepared by extracting with dpkg-deb -x into a new private work dir (resumable with --reuse-work, FFmpeg headers matched to the installed runtime, using Debian Snapshot when versions have left the main repo), then Meson builds with -Dauto_features=disabled -Dlibmpv=true -Dcplayer=false -Dalsa=enabled -Dgl=disabled -Dlua=lua52 -Dbuildtype=release -Dstrip=true -Dbuild-date=false. Playback uses the software RGBA API and ALSA; mpv's optional DRM/GBM/EGL/GL/Vulkan/Wayland/X11 display backends are disabled, not the firmware libraries used by SDL.
  4. Link to firmware. Required shared dependencies link against the existing firmware libraries. Only the locally built libmpv.so.2 and versioned targets ship, as regular copies rather than symlinks, for exFAT support. No SDL/EGL/GLES/Mali/DRM/GBM, glibc or systemd libraries ship.
  5. Publishing gate. ldd -r must resolve all symbols, then a fresh Python process runs tv_media.availability() from stdin with no display or audio device. Any failure retains the private work tree and never publishes the output.

The finished runtime/manifest.json records exact versions, sources, build options, dependency diagnostics and the passing preflight. If a later probe reports ENOSYS or dies by signal, investigate kernel/syscall compatibility separately; do not upgrade firmware or swap libc as a workaround.

Installer safety

Online discovery versus pinned files

The generated Install 227 TV.sh embeds its own release's manager filename, size and SHA-256 plus the release-policy helper. These immutable pins attest that built-in manager, not every future release. In normal online mode the bootstrap fetches https://github.com/1Z99/r36s-tv/releases/latest/download/release.json and accepts the selected newer manager's size/hash from that HTTPS response. It validates format 1, the debian13-arm64-darkosre target, stable version, canonical repository/tag base URL, exact versioned archive names and bounded positive sizes/hash syntax. Archive bytes must then match those values.

The verified manager contains the application's release record. Its bundle fields must agree with discovered metadata, and its code version must match. The application archive is size/hash-checked, extracted with path/type/count/unpacked-size restrictions, and its exact file set and individual hashes are verified before publication. Runtime libraries, fonts, intro, map, globe helper and notices travel inside that archive. HTTPS/repository control remains the online trust root: an old script does not cryptographically authorize future releases independently of that endpoint. Sidecar checksums are not an independent authenticity source, and there is no release-signature verification.

Explicit TV227_RELEASE_BASE/--base or a matching adjacent manager archive selects pinned mode; --source selects an explicit local tree instead. A local three-file bundle does not need a separate metadata file: the verified manager already embeds it. A mirror must supply files matching the script/manager pins; arbitrary newer bytes cannot replace them. Normal bootstrap launches re-extract verified manager code rather than trusting mutable stored modules, retaining its download cache. When latest discovery selects another version, it also caches the manager matching the original script's pins for offline fallback.

A failed network discovery may fall back only to that verified built-in manager cache; malformed metadata fails closed rather than being treated as a successful offline check. Latest-mode Install/Update checks the endpoint again at action time and fails without modifying TV if that check fails. Update refuses downgrades, but returns up-to-date immediately on equal versions: it does not hash the installed application or audit menu integrity in that case. Repair restores the recorded installed version from a matching verified cache or its recorded base, never latest. Legacy installs without a record require the installed version to be recovered by AST parsing and its exact tag metadata fetched; installed code is not executed to identify it.

Runtime and publication boundaries

install.sh validates any present runtime/ manifest: package versions/source, exact file hashes, the library/source/license allowlist and supported relative soname aliases. sh install.sh --list-runtime performs packaging validation without loading the ARM64 library. A present runtime with a missing/invalid manifest fails closed, even if system libmpv is usable. An entirely absent runtime is different: source/host installs may use system libmpv. Official release assembly requires the tested runtime and an AArch64 globe helper. The normal launcher sets the private library path before starting Python; it is not a fresh manifest verifier on every app launch.

System-dependency setup is capability-first: only absent, explicitly mapped Debian 13 packages are planned. The complete APT plan is simulated, audited, version-pinned and simulated again; upgrades, removals, reinstalls and protected graphics, Mali, EGL, GLES, GBM, DRM, libc, systemd and firmware packages are rejected outright. Broken existing libraries are errors, not permission to replace them. The EmulationStation registration is preserved or created as needed (see the shared 227 menu), and every XML change is backed up with a timestamp before anything moves. These are the same boundaries the manager enforces during update and repair.

The shell can bootstrap absent Python/curl/CA certificates under a restricted audited APT plan; an existing old Python is rejected, not upgraded. Manager-only dependencies are checked before its display opens; app/runtime checks follow a confirmed install/update/repair. The source install.sh only probes capabilities and does not install packages. Root or preauthorized sudo -n is required for privileged work, with no password prompt/storage.

Maintenance holds the same data-root app lock as the launcher, a destination install lock and serialized shared-menu work. Close TV first and use the same TV227_DATA override if customized. Publication stages on the card, backs up the previous app and owned launcher/artwork, and attempts restoration on handled failure; failed recovery retains a reported recovery directory. Cancellation is deferred through APT, final publication/rollback and removal. These are not persistent power-loss transactions, and app rollback does not undo system packages. Uninstall retains home-directory TV state, manager storage, shared system/themes and other apps; it is not secure erasure.

Browser selections and card destinations remain scripted; Settings and quality cover an active playback session with opaque menus.

The capture record reports 151 observed frames for France 24 French in watch view and 151–153 per feed for the French, English, Arabic and Spanish matrix, with 640 x 360, 25 fps sources. Counts describe non-empty production Player.frame() RGBA renders, not internal decoder totals or a benchmark. The run used network access and decoding, with null/disabled audio output; the site serves only local media. Source URLs, timestamps, source/image hashes and per-scene playback records are retained, with broadcast credits in NOTICE.md. --validate-only prints a pure plan without loading the app/native libraries, writing files or accessing the network; capture requires --capture-streams.

--skip-intro, --run-seconds N and --capture-after PATH support bounded desktop tests; stock --demo keeps preview state temporary even when a real data-root override is set, and never tunes its sample stations. The website generator bypasses only that demo tuning guard for its isolated playback sessions. Its captures record real PC decoding, not physical input, audio verification, KMSDRM compatibility or handheld performance. Full hardware acceptance needs a separately authorized session covering audio, controls, single playback, matrix load and clean return to ES. None was performed for this documentation audit.

Local builds and preview

A checkout is already the Python source build: it still requires host SDL2/SDL2_ttf and the bundled font/map assets. python3 -B app.py --desktop --demo opens a desktop window with sample data and temporary state; SDL_VIDEODRIVER=dummy switches to headless. The optional ARM64 globe helper falls back on a PC; the ARM64 playback runtime cannot be loaded as a host library. Demo does not need live streams or open real favorites/catalog caches.

Rebuild the globe helper for another architecture with an existing native compiler (gcc, or CC) from globe_filter.c, which ships with the library:

Build a host helper without replacing the shipped ARM64 binary
HOST_HELPER=$(mktemp -d /tmp/tv227-helper.XXXXXXXX)
bash build_globe_filter.sh "$HOST_HELPER/libtvglobe-host.so"
TV227_GLOBE_FILTER="$HOST_HELPER/libtvglobe-host.so" \
  python3 -B app.py --desktop --demo

The output parent must already exist; rebuilding never touches firmware, and the app-local native/ directory is separate from the mpv runtime manifest. For a host staging test without a real card:

Automated isolated staging and registration checks
PYTHONDONTWRITEBYTECODE=1 TV_MEDIA_AO=null \
  python3 -B -m unittest test_packaging test_system

These fixtures supply temporary card/configuration paths, avoiding the live /etc/emulationstation/es_systems.cfg. Do not assume --prefix /tmp/... alone isolates every integration path. Host staging requires working host libraries and a fixture without the ARM64 runtime; the packaging suite constructs that fixture. Installer tests also use temporary data roots to avoid live app-lock/state writes.

Device deployment is a separate, explicitly authorized operation, not a host validation step. deploy.sh accepts TV227_SSH_USER, TV227_SSH_HOST, TV227_SSH_KEY and TV227_PREFIX. It validates local syntax/runtime packaging, transfers a temporary allowlisted bundle, runs its no-display preflight remotely, then installs using already-authorized sudo -n. It does not start TV, restart ES or kill a running app. No deployment or hardware actions were run for this audit.

Scope and omissions

Shipped: the atlas, country-only loading, favorites/recent snapshots, local search filters, manual HTTP health rechecks, fullscreen single video, experimental matrix playback with focused audio and rendition preferences, CRT overlay, world-spin settings, shared 227 registration and release-verified maintenance. Not shipped or promised: worldwide search/preloading, universal firmware compatibility, transcoding, a hard SD-only decoder limit, matrix maximize, station uptime/speed guarantees, signed release authentication, power-loss-safe rollback or automatic playback after install. Same-version Update is not an integrity audit; use Repair.

The desktop plugin keeps its own life: Omarchy hides the HLS proxy, QtMultimedia embedded playback, and the looping health scanner behind desktop windows. When those parts change upstream, the handheld port considers them separate projects, not silently shared behavior.
