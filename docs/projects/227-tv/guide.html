227 TV / Get Started

From the card's tools folder to 227 > 227 TV.

Copy one installer to your games card, connect to Wi-Fi, and install from Tools. Then open 227 > 227 TV to explore countries and watch live channels. You do not need 227 AI, SSH or terminal commands.

R36S / dArkOSRELatest: 227 TV 1.0.4GitHub Releases ↗

Before you start

This release targets an R36S, aarch64, running dArkOSRE based on Debian 13 (trixie), including the tested build 03082026 and kernel 4.4.189. Original Ubuntu-based ArkOS, AmberELEC, 32-bit images and arbitrary clones are not supported by the shipped binaries. The manager checks the platform before downloading/installing the application; the smaller manager may already have downloaded by then.

The normal one-file install needs internet. Live television and new country lists also need a connection; Wi-Fi adapter support comes from your firmware, not TV. Keep the handheld powered during installation and leave at least 200 MiB free on the destination card as a practical starting budget for downloads, unpacking and rollback, not an exact installed size. Missing system packages need separate space on the system partition.

Technical requirements
  • Python 3.10 or newer, plus the firmware's SDL2 and SDL2_ttf libraries.
  • Working SDL KMSDRM and Mali drivers on the handheld for display.
  • Root or existing noninteractive sudo -n authorization for installation; no password is requested or stored.
  • A writable SD card actually mounted at /roms or /roms2.
  • Wi-Fi for live streams and for downloading any missing Debian 13 packages.

Installation

One-file installer (online, recommended)

Download Install.227.TV.sh ↗ from GitHub Releases. With the handheld powered off, copy it to the games card's existing tools folder alongside the game folders. You can rename it Install 227 TV.sh for a tidy menu. Safely eject the card, put it back, and boot the handheld.

Use the release installer, not a source-code ZIP, the source install227tv.sh template or install.sh. If your computer cannot see the games partition, do not format the card; use a reader/OS that can access it.

  1. Enable Wi-Fi.
  2. Open Tools > Install 227 TV.
  3. Choose the destination card: use Left/Right on the destination row to select SD1 (/roms) or SD2 (/roms2). An unmounted or unwritable card is unavailable. If 227 AI already has a 227 menu, choose that card.
  4. Select Install, confirm Yes, and wait for completion.
  5. Reload or restart EmulationStation's menu yourself when ready.
  6. Open 227 > 227 TV. TV does not install into Ports.

The installer downloads a controller-driven manager, then the complete app, artwork, fonts and matching playback engine. Downloads are checked before use. Obtain the script from the project's trusted release page: checksums detect mismatched files, but there is no independent publisher signature. See the build notes for the online and offline trust chains.

Offline Application Bundle

For a card without network access, download three matching files from the same release page and put them together in the card's tools directory:

  • Install 227 TV.sh
  • melkor227-tv-manager-1.0.4.tar.gz
  • melkor227-tv-1.0.4-darkosre-arm64.tar.gz

The two archives make application installation offline; they do not contain a replacement operating system or every Debian package. Missing compatible system packages still come from the Debian repositories, and existing working firmware dependencies are reused.

Keep matching files together. A matching manager archive beside the script automatically selects the local, pinned release rather than latest-release discovery. The script verifies that manager; its embedded release record verifies the application. No separate release.json download is needed for this three-file method. To return to normal online updates later, move the two copied archives out of the installer's folder and reopen the script with Wi-Fi.

Advanced mirror override

Advanced users can set an explicit HTTPS mirror or file:// release directory. This pins Install/Update to that release rather than discovering latest:

Point the bootstrap at a hosted or local release
TV227_RELEASE_BASE="https://github.com/1Z99/r36s-tv/releases/download/v1.0.4/" \
  sh 'Install 227 TV.sh' --cli --roms /roms --action install --yes

Use a matching script and both archives. An override does not disable size/hash checks and is not a way to make an old script accept arbitrary new files. Repair still targets the installed version.

Choose a card

The manager treats SD1 (/roms) and SD2 (/roms2) as independent destinations; unmounted or read-only cards cannot be selected. Installing on the other card does not move or delete an earlier copy.

The card picker is not a migration tool. Back up and maintain each copy deliberately, and choose the card you intend to update.

The bootstrap stores its manager on the card containing the script when eligible, otherwise a writable mounted SD2, then SD1. The app destination is a separate explicit choice. Keep the tools/227-tv-manager/ support folder and Install 227 TV shortcut for maintenance. Both app copies use the same default home-directory TV state, not separate per-card favorites.

The shared 227 menu

If an EmulationStation system <name>227</name> already exists, its directory, command, extensions, theme and unrelated metadata are preserved. For example, it can point to /roms/227ai/, alongside 227 AI.sh. TV adds only its own launcher, artwork and gamelist entry, preserving 227 AI statistics and other projects.

You do not need an existing 227 system or 227 AI. If the system is absent, TV creates it automatically using <card>/227ai/. Reloading EmulationStation only makes that new menu visible; you do not create it yourself. If 227 is registered on another card, the installer refuses to silently retarget it: choose that card instead. The existing registration must use a direct child of the selected card for the relative launcher.

Only TV's own historical Ports entry is migrated, and only when its launcher is identified as TV's file. Unrelated Ports games are never removed, and a Tools fallback remains. Changed EmulationStation XML receives timestamped backups beside the original files.

Some 227 AI manager versions can remove other shared entries. Do not assume a newly downloaded AI bootstrap updates a complete cached manager backend. Back up the shared menu before AI maintenance, and verify that manager's preservation behavior separately. If TV's menu entry is lost, close TV and run Repair in the TV manager. TV does not modify AI's manager, models or chats.

First launch

Open 227 > 227 TV after refreshing the menu. The short 19-frame intro plays on each normal launch; A, B or Start skips it. An empty World list saying Choose a country is normal: startup does not download the world's channels.

  1. Press Start, choose Browse countries, move Up/Down and confirm a country with A. This is the easiest first selection; you can explore the globe with the left-stick pointer later.
  2. Wait for its channel list. Use Up/Down to select a station and A to watch. Left/Right pages the list. Try another station if the broadcaster is unavailable.
  3. Playback already fills the screen. The header, footer and pointer hide after about 2.5 seconds without input. A pauses/resumes; L2/R2 lowers/raises volume.
  4. Press B to stop playback and return to browsing. With no menu open, Y saves/removes the selected station as a favorite; L1/R1 switches World, Favorites and Recent.
  5. To leave TV, use Start > Exit TV, select Exit to EmulationStation and confirm with A. B first clears country/search filters when browsing, then opens the exit prompt from the unfiltered world.

Press X to search the channels already loaded for that country, not a worldwide service or a country finder. Search can also filter saved Favorites/Recent. The keyboard opens before loading, but cannot find unseen channels. See the search reference.

If playback is slow, try Start > Resolution / frame rate and a lower advertised format, or keep Auto / up to 480p. Some broadcasters offer only HD; TV warns and continues rather than creating a lower-quality stream. Start with one channel before trying the experimental matrix.

Launch handheld TV only through EmulationStation. The app needs exclusive use of the handheld display and controller while the menu waits. Do not start it remotely or in the background beside EmulationStation. Desktop previews are a separate developer mode.

Update and remove

Close TV first; the installer does not kill the app, start TV, restart EmulationStation, reboot, upgrade firmware or alter Wi-Fi configuration.

Manager actions
ActionWhat happens
InstallInstalls beside 227 AI after verifying the application archive; preserves an existing 227 registration.
UpdateIn normal online mode, checks the repository's newest stable release, verifies a newer bundle and refuses downgrades. A same-version result is a version check, not an installed-file integrity audit: use Repair for missing/changed files. An offline latest check fails safely; explicit mirrors/local bundles compare their pinned version instead.
RepairRestores exactly the installed release, preferring installed-release.json beside the app. It can use a matching verified application cache offline. Without a record, the version is read from installed code without executing it and its exact tag metadata is fetched, so that recovery needs network access. Repair never guesses "latest".
Uninstall TVRemoves TV's program and launchers, not 227 AI, the shared 227 registration or themes. Favorites, history, catalog caches and preferences in ~/.local/share/melkor227-tv are deliberately retained.

B asks to cancel. Downloads are cancellable; an in-progress APT transaction or final publication is allowed to finish safely before cancellation takes effect. On failure A retries, X shows details and B returns to the menu.

Installers from v1.0.0/v1.0.1 remain pinned to their own version: replace that Tools script once with the newest Install 227 TV.sh from the Releases page ↗. From v1.0.2 onward, future stable releases are available through Update in normal online mode; explicit mirror/local-bundle choices remain pinned.

Back up before maintenance. Close TV and copy ~/.local/share/melkor227-tv/state.json to a separate safe location; it holds favorites, the last 50 recent stations and preferences. Copy the entire data directory if you also want country caches and health records. State normally lives in the user's home, not on the games card. To restore, keep TV closed and restore the saved files to the same data root, retaining an untouched backup.

Dependencies and safety

The complete app bundle includes its own matching playback engine. You do not need to install a distribution mpv package or replace graphics drivers. Working firmware dependencies are reused; only missing, approved Debian 13 packages may be added after a simulated, version-pinned safety check. Existing broken libraries or a plan requiring upgrades, removals or protected graphics/base-system changes cause an error.

Missing Python, curl or CA certificates can be bootstrapped under the same restricted policy; an existing Python older than 3.10 is not upgraded. System packages remain after TV removal and are outside app-file rollback. Do not power off during package setup or final installation. Rollback after a handled failure is not a guarantee of recovery from power loss. The technical safety model explains the boundaries.

Troubleshooting

Tools does not show the installer, or 227 is missing

Check that the release script is in the games card's existing tools folder and ends in .sh, then reload the menu. A scraped-games-only filter can hide an unregistered script. After successful installation, reload/restart EmulationStation; if TV is still missing, choose its installed card and run Repair. Existing shared 227 directories are preserved, so the path need not literally be 227ai/.

The installer closes before a window appears

Inspect ~/.local/state/melkor227-tv/bootstrap.log (or $XDG_STATE_HOME/melkor227-tv/bootstrap.log when overridden). This records early download, Python, platform and pre-display failures. A text error dialog is only available with a usable terminal and dialog utility. Check network access, supported firmware and existing noninteractive sudo authorization; relaunch after correcting the reported error.

My card is unavailable, or 227 is registered on another card

The card must actually be mounted at /roms or /roms2, writable and not redirected by a symlink. Do not create a directory to imitate an absent card or format it to fix this. If 227 already points at the other card, choose that card: TV refuses to silently move the shared menu.

Where are the other logs and downloads?

The graphical manager log is ~/.local/state/melkor227-tv/installer.log; the launcher appends to ~/.local/share/melkor227-tv/app.log (under TV227_DATA if overridden). Application archives cache on the selected app card at tools/227-tv-manager/cache; manager archives cache on the bootstrap's Tools card at tools/.227-tv-downloads. Review logs for private URLs and paths before sharing.

The installer says a dependency ABI is incompatible

Use matching firmware or rebuild the runtime against the tested recipe. Do not replace Mali/GBM libraries or install foreign distribution packages.

A download or latest-release check fails

Check Wi-Fi, free card/root-partition space and the exact error. In the manager, X opens failure details and A retries. For offline files, use the matching script and two archives from one release. Never bypass a checksum mismatch. Offline Repair needs its installed-release record and matching cached application archive; the bootstrap also needs a verified cached manager. A first-ever one-file launch cannot work offline without the three-file bundle.

World is empty, search finds nothing, or a country looks stale

Open Start > Browse countries first, and wait for loading. Search only filters the selected country's loaded channels or saved Favorites/Recent; it does not fetch worldwide results. Clear a search with the keyboard's CLEAR then FIND. Country/query filters also apply to Favorites/Recent; use World / clear filters before switching tabs to see all saved entries. Try Refresh selected country online; a failed fetch can retain an older country cache, and some countries have no playlist.

A channel buffers, says SIGNAL UNAVAILABLE, or has no sound

Try another channel to distinguish a broadcaster/region problem from a connection problem. Reopen the station after checking Wi-Fi. For slow video, choose a lower advertised quality; Auto cannot manufacture SD from an HD-only broadcast. Press A if paused and raise volume with R2; in matrix mode, focus a populated cell to hear it. Recheck station health tests HTTP reachability, not working video or audio.

TV closes immediately, or competes with EmulationStation

Read app.log for a duplicate launch, missing runtime, invalid JSON or display-ownership error. Launch from 227 > 227 TV or its Tools fallback, never a parallel remote/background process. If a normal menu launch still competes, stop testing and report it rather than disabling the guard; multiple sessions can also cause conflicts. Close TV before Repair. Back up malformed state before attempting recovery; do not delete favorites as a first troubleshooting step.

Still blocked? File an issue ↗ with firmware/build, architecture, chosen card, installed version, action, exact error and relevant log excerpts. Say whether an image is an offline preview or a real device capture.

Advanced CLI

The bootstrap accepts the same actions over SSH through an explicit headless --cli mode, using the graphical manager's backend without opening its display. Changes require --roms and --yes; substitute /roms2 only when that is the intended mounted app card. Do not start the graphical manager remotely alongside EmulationStation.

Read-only destination and 227 registration validation
sh 'Install 227 TV.sh' --cli --roms /roms --action install --dry-run
Install from a complete local source tree
sh install227tv.sh --source /path/to/melkor227-tv \
  --cli --roms /roms --action install --yes
Remove TV only; saved TV data and 227 AI are kept
sh 'Install 227 TV.sh' --cli --roms /roms --action uninstall --yes

This is not a write-free standalone-bootstrap command. Bootstrap startup can log, download and replace verified manager files before the CLI dry-run runs. The manager dry-run itself only validates the card and shared-menu destination: it does not install packages, download the application, change menus or prove sufficient staging space. Missing bootstrap tools are not installed in dry-run mode. --es-cfg PATH and --themes PATH support explicit integration/test destinations; use isolated fixtures rather than a live config for host testing.
